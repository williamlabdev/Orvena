## 這把尺要量什麼(不是「更難」,是 0.5.0 打開的新軸)

v2 的軸(查證/枚舉/多跳/重讀/語意歸納)量的是「證據**取得**」。0.5.0 給了
loop 一個帶預算的累積視窗(4096 tokens,丟最舊)之後,取得幾乎不再是
分水嶺——v2 重飽和就是這句話的讀數。新的分水嶺往後移了一格:

**證據視窗是有限資源時,模型會不會管理它。**

「管理」拆開是三個可觀察的行為,對應三個題型方向(下方):

1. **排序**——把最後才用的證據最後讀,讓它活到要用的那一步;
2. **重讀決策**——看到 dropped 標記後,知道被擠掉的證據要重讀,而不是
   憑殘像編一個值(接地規則擋編造,但擋不住「以為自己還記得」);
3. **讀的節制**——必要證據總量逼近預算時,每一筆多餘的讀都會擠掉一筆
   必要的;讀太多和讀太少一樣會死。

這不是 v2 的調參。v2 的難度來自資訊結構(值外觀無從分辨、針不可 grep),
v3 的難度來自**必要證據總量與視窗容量的比值**——兩把尺的軸正交,
數字永不 pool(可比鍵第一元素換成 `capability-v3.yaml @ <commit>`)。

## 機制基礎(0.5.0 實作事實,造題前必須知道的硬約束)

逐條查碼(`agent/driver.rs`、`util.rs`),不是設計願望:

- **保留語意**(`driver.rs:72-94`):由最新往回整塊保留,直到 4096 耗盡;
  **最新塊永遠保留**(即使單塊獨自超預算);擠掉時窗口自報
  `(evidence from steps 1–k dropped: evidence budget reached)`。
- **模型每步是無狀態呼叫**:證據窗**就是**模型對本 run 的全部記憶。
  被擠掉=真的忘了;接地規則(prompt 紀律,兩姿態同帶)會把編造擋下,
  但模型看不看得懂 dropped 標記、會不會回去重讀,是行為,不是保證。
- **批次的窗行為是斷崖,不是漸縮**:一步 = 一次呼叫、actions 無上限
  (v2 教訓),一步的全部工具輸出合成**一個塊**(`driver.rs:380/433`,
  兩腿皆一步一塊)。擠出以**整塊**為單位:批次巨塊是最新塊時整包保留
  (**即使單塊超過 4096——最新塊豁免上限**),一旦有新塊落地就被
  整包擠掉——窗從「什麼都在」跳到「幾乎全沒」。推論兩條:
  (i) **單回合題擋不住批次**:第 1 步全讀、第 2 步 edit,巨塊還在窗內,
  題目整個被繞過——所以 v3 **每一題**都必須有多回合狀態揭露(條件 11
  是普適條件,不是某類題的);(ii) 多回合下批次模型的死法簽名是
  **斷崖後重讀**(或斷崖後編造被接地攔下)——這本身是可分類的死法,
  遙測要能看到它。
- **gate 每步無條件跑,回饋與該步工具證據合塊、吃同一個預算**
  (`driver.rs:393` 的 gate 迴圈不看模型有沒有動作;`driver.rs:429-433`
  合塊)。兩個推論:(i) 收斂族的視窗壓力計算必須含逐回合 check 輸出;
  (ii) **「check 揭露」與批次讀是同步的**——模型第 1 步只批次讀、
  不 edit,gate 照跑,揭露內容跟整包讀進來的證據落在**同一塊**,
  下一步它還是最新塊、整包豁免保留。所以「有揭露層」不等於「擋得住
  批次」:揭露必須依賴**模型先改變的狀態**(修完 k 才揭 k+1)才真的
  逼出跨步存活問題。這條是 fresh-eyes 打穿 N1/N2 第一版的機制,
  寫進機制基礎,凍題自我測試(條件 11)以它為準。
- **計價**(`util.rs:9`):`estimate_tokens = ⌈chars/4⌉`。尺寸換算:
  50 行 × 80 字元 ≈ 4000 chars ≈ **1000 tokens**;READ 與 RUN **共用**
  同一截斷(`cap_run_output`,100 行/8KB ≈ 頂格 **2048 tokens**,
  `driver.rs:262-268`)——現行語料 ≤50 行從未觸頂,但 v3 的「滿版檔」
  設計上限就是 100 行/8KB,超過會被截(截斷有標記行,不是靜默)。
  → 4096 的窗 ≈ **4 筆滿版 50 行讀**,或 2 筆頂格 RUN 輸出。
  題目的壓力就從這個比值來:必要證據 3–5 筆滿版塊,總量貼著預算。
- **`MAX_STEPS = 8` 照舊是尺的凍結常數**;最壞情況(不批次、一步一動作)
  8 個工具動作內可解,含最後那次 write——v2 條件 9 原封繼承。

## 設計條件(v1 的 1–4、v2 的 5–9 全部繼承,加三條)

10. **壓力來自比值,必要性仍來自資訊結構**。「必要證據總量逼近 4096」
    製造的是管理問題,不是解法門檻——判過/不過的仍然是資訊結構
    (值不讀不知道、外觀無從分辨)。用預算擋暴力路徑在 v2 已判定是
    假必要性(擋掉的是不批次的模型),v3 不重蹈:視窗預算決定
    「怎麼讀才活得下來」,永不決定「讀不讀得到」。
11. **狀態依賴的逐回合揭露是每一題的必要條件**——「多回合」三個字
    不夠精確,被 fresh-eyes 打穿過一次:gate 每步無條件跑,揭露與
    批次讀同步落在同一塊(機制基礎最後一條),所以光有 check 揭露
    擋不住「第 1 步全讀不 edit、第 2 步帶著整包+揭露收工」的走法。
    擋得住的只有一種:**揭露 k+1 依賴模型先完成修正 k**(真實狀態
    變化),讓必要證據被迫跨 ≥2 個「自己會推塊進 log」的步存活。
    **v3 凍選的每一題都必須過這道檢查**:寫出「批次模型第 1 步讀完
    全語料(gate 同步揭露算給它)」的走法,若它能在第 2 步收工,
    題目重造。
12. **尺對 agent 常數的敏感依賴要明寫**。4096 是 agent 行為常數
    (0.5.0 的一部分),不是尺的常數;v3 的壓力點是**對著它**校準的。
    agent 換版(改預算、改保留策略、學會摘要)→ v3 讀數跳——這不是
    尺壞了,是尺在做 E 哨兵在 v2 做過的事:**偵測 agent 質變**。
    可比鍵第四元(agent 版本)照舊承擔區分;v3 凍題時必須指定
    「本尺的壓力係數以 agent 0.5.0(EVIDENCE_BUDGET_TOKENS=4096)
    為基準」寫進檔頭。

草擬期追加兩條(0807 兩支平行草稿各貢獻一條,查碼所得,非設計願望;
draft-5 合併後兩條皆為全題硬約束):

13. **writable 目標必須是封閉、等寬凍結的 key 集,且每 key 有嚴格值
    格式**。理由:writable 檔內容每步重印進 prompt,計價在 role 預算、
    不在證據預算(`context.rs:56-74`)——它是免費、永不被擠出的暫存板。
    沒有這條,任何 v3 題都可以「把針抄進 writable、完全不管理視窗」
    通過,且遙測分不出它與好排序(兩者 dropped_* 皆 0)。封法:值一律
    答案等寬佔位 + byte cap = 解完尺寸+4B + 行數凍結 + guard 排在
    chain 檢查之前——stash 與進度互斥(draft-4 系,兩輪 verifier 實跑
    驗證;N4 的 {1,4} 位寬閘同源:無界 [0-9]+ 曾讓 min·max 併接塞縫,
    哨兵 6 動作變綠)。
14. **必要證據不可被定向 SEARCH 廉價提取**。理由:SEARCH 只回匹配行
    (`driver.rs:340-356`),READ 截斷提示還主動推薦它——值若坐在可辨識
    行上,成本 ~1 行而非整塊,壓力係數蒸發(draft-4 的 row-keyed 鏈
    正是這樣被 alt 支實測打穿:`SEARCH a37` ~32 tok 對 READ ~2000 tok)。
    封法:記錄**均勻**(每行同形)、操作值**位置式**(檔案末行)——
    不讀檔就沒有任何 pattern 能單出它;catch-all SEARCH 帶 `path:line:`
    前綴,~1.25× 於被替代的 READ,且 MAX_HITS=200 擋跨檔掃。
    豁免:N1 的針(pin 檔)刻意 row-keyed——針本來就該便宜重取,
    量的是「回去拿」這個決策,dropped_research 讓這條路可見。

## 儀器前置(先於一切題目,這是本 slice 的第一刀)

  只有次數答不了);
- `dropped_reread`:dropped 標記出現後,對已擠出路徑的重複 READ 計數

  題造出來壓不到預算,量的就不是管理)。

這是一個獨立 code slice(量測儀器,不是 agent 行為;不換 agent 版號,
report schema 加欄位)。**先儀器、再探針、再題**——順序不可換。

## 題目草稿(0807 深夜,第八棒):N1/N3/N4 draft-4 落地
