  # ══ N4 — sentinel (capv3-sentinel-span) ══════════════════════════════════
  #
  # Designed to read low/zero in BOTH cells on agent 0.5.0 and to flip red
  # the moment the agent learns retention/summarization — v3's E, per
  # ruling iv. The alt session's span shape, adopted per the merge ruling
  # (this also RESOLVES flag f3: necessary evidence is now 4 blocks ≈
  # 1.75x 4096, inside the ruled 1.5–2x band). Corpora are de-anchored
  # (no index column, random fields, pairwise-distinct row counts —
  # `deanchored()` asserts; see N1); tails and spans asserted >= 1000.
  #
  # Mechanism: the carried value is a SPAN (largest minus smallest of the
  # values ending refs/f1..f4.txt). The running state is a (min,max) PAIR;
  # the single writable slot is width-gated to <= 4 digits, so it carries at
  # most ONE number. A span cannot be extended by a new term without the
  # side it does not record. Stages: span(f1,f2) → +f3 → +f4, each stage
  # moves the target (asserted), reveals follow correct stage values only.
  #
  # Width gate provenance (draft-5): the alt draft's format regex was an
  # unbounded [0-9]+ — min·max CONCATENATED into the slot passes it, the
  # writable reprint (context.rs:56-73, outside the evidence budget) hands
  # it back every step, and the sentinel walks in 6 actions. The {1,4}
  # width gate + byte cap close the pair-carry; the generator regression-
  # tests the concat stash (guard preempts, no reveal).
  #
  # RESIDUAL WALKS — documented and generator-asserted, not denied. The
  # check is stateless and tests the final span first, and span = f(the two
  # global extremes), so:
  #   (i) 2-extreme close: a model holding both global extremes closes
  #       without walking stages. Extremes sit in NON-ADJACENT files
  #       (min: f2, max: f4) and corpora are uniform — no a-priori signal
  #       says which pair matters, so a blind 2-read try is a 1-in-6 pair
  #       guess at ~3 actions per try.
  #   (ii) disciplined extreme-tracking: single-slot carry of one running
  #       extreme + eviction-aware ordering can pass in ~6-7 actions. That
  #       IS elite window management — if a cell turns green, verify the
  #       action log (which files were read, what interim values were
  #       written) before reading it as capability arrival; do not take the
  #       pass column at face value. A stage-skip (correct span(f1..f3)
  #       written without stage A ever passing) is part of this signature.
  #
  # Expected 0.5.0 deaths (arithmetic, not luck):
  #   JIT walk: every stage beyond A needs a term whose block is gone —
  #     re-read loops burn steps (dropped_reread/research high, steps
  #     exhaust);
  #   batch walk: ~7.3k giant read is newest-exempt for one step, then
  #     cliff-evicted whole; stage arithmetic restarts from nothing.
  #   Three blocks never coexist (asserted: f1+f2+f3 > 4096), and stage C
  #   needs information from three files' tails at once unless an extreme
  #   is carried — which the slot width fights.
  #
  # Condition 11 self-test: batch close at s2 fails — stage reveals hang on
  # correct stage values, and only stage A is computable from the giant
  # newest block at s2 (that is one stage, not the task — the giant is gone
  # at s3 and stages B/C still need their terms). No compute channel (RUN
  # fixed-argv); no search shortcut (de-anchored positional tails, and the
  # spans themselves appear in no file).
