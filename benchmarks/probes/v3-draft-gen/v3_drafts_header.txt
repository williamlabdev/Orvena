# What every task here shares (mechanism dossier, verified in code 0807):

# * Sequential first-problem-only check (H pattern): reveal k+1 exists only
#   after fix k — real state dependency, per design condition 11.
# * UNIFORM / POSITIONAL CORPORA (condition 14, from the alt draft): fat
#   records are fixed-shape, every record ends in a same-shape value, and
#   the operative value is the file's LAST line. No pattern formable
#   without having read the file singles it out; a catch-all SEARCH
#   returns every line with a path:line: prefix (~1.25x the READ it would
#   replace) and MAX_HITS=200 stops multi-file sweeps. N1's pin file is
#   the deliberate exemption (see its block: the needle is SUPPOSED to be
#   cheap to re-acquire; the go-back is the measurement).
# * ARMOR CHAIN (from draft-4, now file-level): which pool file (N1, N3)
#   or which pin key (N1 round 4) settles round k+1 is derived from the
#   CORRECT value of field k via `cksum` at runtime. Why: condition 11's
#   literal self-test kills every plaintext-mapping design — reading
#   check.sh reveals the full map, and the step-1 giant block is still the
#   newest block at step 2 (newest-block exemption), so a one-shot full
#   write closes at step 2 with zero window pressure (v2-H has exactly
#   this property). With the armor the map is not mentally recoverable
#   (CRC is not text reasoning) and no compute channel exists: RUN
#   executes only pre-declared fixed-argv commands (.orvena/commands.yaml,
#   tools/shell.rs). Keys are unknowable until each reveal, and reveals
#   only follow real fixes. Honest walkers never see the armor: each
#   complaint names the file/key in plaintext at runtime.
# * Anti-stash guards (from draft-4): placeholders are answer-width, the
#   byte cap is the exact solved size + 4B, exact line count + grep -qxF
#   frozen lines — ALL ordered BEFORE the chain checks, so honest walks
#   are size-constant and any insertion preempts the next round reveal.
#   Writable contents print into the prompt each step (context.rs:56-73)
#   outside the 4096 evidence budget, and the 8000 whole-prompt budget
#   does NOT self-limit a stash — gate ordering is what closes the hole:
#   stash and progress are mutually exclusive. N4 adds a {1,4} digit
#   width gate for the same reason (the pair-carry stash).
# * Complaints POINT at the source and never quote the expected literal
#   (L-forensics 0807: quoted literals in feedback became the wrong
#   answer; freshness traps are a DIFFERENT axis and must not contaminate
#   these).
# * Fat refs are deliberately under the READ/RUN truncation edge (100
#   lines / 8KB, cap_run_output), so one READ returns the whole file
#   untruncated: N1 pool 99 lines / ~8.1KB ≈ 2030 tok; N3/N4 refs 90
#   lines / ~7.1KB ≈ 1778 tok.
